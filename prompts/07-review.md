# 07 · Revisar / Revisar / Review

Úsalo con la carpeta, vista previa o URL real. Preparar esta revisión no autoriza por sí solo a publicar.

~~~text
Revisa esta web para un negocio de Barcelona antes de entregarla. Responde en el idioma elegido: catalán, español de España o inglés. Lee bcn-release-review y las instrucciones del proyecto si puedes acceder a ellas.

Identifica qué artefacto puedes inspeccionar: código, vista previa, URL pública o solo capturas. No afirmes haber probado lo que no está accesible. Si falta el artefacto, pídeme el mínimo necesario y haz como máximo dos preguntas.

En este repositorio, revisa package.json y las instrucciones actuales. Ejecuta las pruebas/build pertinentes y npm run check:release cuando evalúes una entrega real. No cambies una aprobación o un digest para hacer pasar el control. Si el ejemplo es una demo, indícalo; no debe superar el control como web real aprobada.

Comprueba con evidencia:
1. Datos reales y aprobados: oferta, precios/carta, horarios, dirección/zona, contacto y pruebas. Sin placeholders ni reseñas ficticias en una entrega real.
2. Tarea principal en móvil: entender la oferta, encontrar el dato necesario y llegar al contacto correcto. Verifica los destinos; distingue solicitud de reserva confirmada.
3. Catalán, español e inglés: navegación, cambio de idioma, coherencia de hechos y textos largos. La revisión automática no sustituye la revisión competente/nativa.
4. Teclado, foco visible, encabezados, alternativas de imágenes, contraste, zoom y desbordamientos. Inspecciona móvil y escritorio si hay herramientas.
5. Imágenes con permiso y recursos/redes de terceros. No concluyas que no se tratan datos porque no hay formulario.
6. Información legal/privacidad aplicable: hechos del propietario y fuentes oficiales actuales. No certifiques cumplimiento legal automáticamente.
7. Si se publica la marca opcional “tanwithme”, aprobación informada del propietario, minúsculas exactas, salida pública verificable y retirada sencilla. Sin balizas ni identificadores de visitantes.
8. Propiedad, costes recurrentes, edición, entrega y una forma de recuperar una versión funcional.

Entrega una tabla corta con comprobación, evidencia, resultado y acción. Usa resultados honestos: pasa, falla, no comprobado o requiere revisión humana. Separa bloqueos de mejoras opcionales.

Corrige los defectos locales reversibles que estén autorizados y repite las comprobaciones afectadas. No publiques por el hecho de pasar pruebas. Termina con el estado real, el bloqueo concreto si existe y una prueba con una persona que no conozca la web: completar la tarea principal sin ayuda.
~~~
