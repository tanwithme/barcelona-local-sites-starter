# What this starter is trying to make possible

Date: 2026-09-07.

## Goal

Help an AI beginner in Barcelona move from “I could build websites” to one useful, intentionally designed, owner-reviewed small-business website, while learning enough to explain and maintain it.

## Source and what it actually establishes

Tan supplied a 3:37 captioned video about helping young people in Barcelona build local-business websites. The full working caption transcript was reviewed and the rendered video was sampled across its duration. This was not a continuous audiovisual watch. The private video/transcript and personal working files are not redistributed here.

The source intent is: talk to real owners, solve a useful problem, avoid spending on tools before there is demand, make good design accessible, and let beginners ask for help. The video contains illustrative revenue/subscription/price examples, plus proposed watermark monitoring and outreach. Those are source claims or proposals; they are not validated earnings, guaranteed platform access, an operating monitoring service or permission to contact third parties.

This version also draws on Tan's previous local-website pack, inspected design/learning instructions and bounded repository history: conversational help, structured context, explicit state, one practical repetition and feedback. We extracted these operating choices; we did not copy private memories, client records or platform skill packages into the repository. The public early [TanOS README](https://github.com/tanwithme/tan-os) describes an intended copilot and explicitly labels its then-current state as a skeleton, which reinforces the distinction between an idea and an executed capability. It does not establish present product maturity.

## The controlling bottleneck

A novice is otherwise asked to decide scope, tool, design, copy, privacy, pricing and release at once. More prompts alone will not solve that. The first step needs one customer task and one successful example, with enough help to understand the next choice.

## What we removed

- Mandatory subscriptions or spending before a client conversation.
- A required database, login, AI API key, live Instagram feed or customer form.
- The assumption that ChatGPT Sites is available to every Barcelona resident.
- Promises that a watermark can find every generated site or judge design quality automatically.
- Automatic outreach, public shaming, free-redesign promises or purchases triggered by a scan.
- A single visual template imposed on every business.

## What we kept and made testable

| Choice | Why | Disconfirming test |
| --- | --- | --- |
| A conversational start file and five small skills | Beginner can ask for one next action | New learner cannot start without expert explanation |
| Three complete languages and one fact set | Local customers get consistent information | Price/hours changes differ between pages |
| Static files with optional tools | Ordinary failures remain cheap | Core contact or content disappears without JavaScript |
| Explicit draft/live states and content-bound approval | A changed source should not inherit stale acceptance | Edit facts or image bytes after approval; release must fail |
| Disclosed optional public provenance | Identify participating sites without tracking visitors | Marker-only, copied, removed or wrong-origin evidence is called verified |
| Bounded source research | Borrow principles with specific evidence | A “best” label is asserted without an actual inspection basis |

## Strongest recommendation

Start with one business, one main action and a small content site. Budget the three-language review, factual verification, owner handoff and later editing method explicitly. A few-hundred-euro offer must shrink when those requirements cannot fit; it should not make them disappear. Do not recommend €100 projects as a reliable income formula.

## Gradual agency

The learner first recognises one customer problem, then fills a supported brief, edits one example, explains a design decision, tests the result, and handles a real owner review. Only then add a maintained booking service, CMS or other integration. The tool should offer help and recovery throughout, without silently promoting itself into authority over the business.

## Remaining proof

File tests and AI language review establish a working starter, not native-speaker approval, profitable demand, universal legal compliance or completed third-party integration. The next useful observation is a Barcelona beginner completing one demo and three fluent readers reviewing the customer journey, followed by an owner performing the agreed edit or update request.
